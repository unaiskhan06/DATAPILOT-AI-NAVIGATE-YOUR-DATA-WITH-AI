# Project development

- The frontend is vanilla HTML/CSS/JavaScript served by Flask; there is no Node build step.
- The existing virtual environment is at the repository root (`.venv`), not inside `backend`.
- From the repository root in PowerShell, start the app with `& ".venv/Scripts/python.exe" "backend/app.py"`. The default address is `http://127.0.0.1:5000`. NOTE: when the agent starts the server via its `exec` tool, the process is a child of the agent's shell and gets killed when the session is cleaned up — the app then dies mid-session with `ERR_CONNECTION_REFUSED` (there is no login limit; the process is simply gone). For a server that persists, run the command yourself in your own terminal, or start it detached with `Start-Process -FilePath ".venv/Scripts/python.exe" -ArgumentList "backend/app.py" -WindowStyle Hidden`.
- LAN / phone access: `backend/.env` sets `HOST=0.0.0.0`, so the app is reachable at `http://192.168.1.7:5000` (this PC's Wi-Fi IP) from other devices on the same network. `APP_BASE_URL` and `GOOGLE_REDIRECT_URI` are intentionally left unset so URLs auto-derive from `request.host_url` — the PC gets `http://127.0.0.1:5000/...` and the phone gets `http://192.168.1.7:5000/...` automatically. For Google login to work on the phone, `http://192.168.1.7:5000/api/auth/google/callback` must be added to the OAuth client's Authorized redirect URIs in Google Cloud Console (alongside the `127.0.0.1` one). Windows Firewall also needs an inbound rule: run `netsh advfirewall firewall add rule name="DataPilot AI 5000" dir=in action=allow protocol=TCP localport=5000` in an elevated (admin) terminal.
- Browser regression checks: with the server running, execute `& ".venv/Scripts/python.exe" "_check_dashboard.py"`. This uses Playwright 1.55.0, installed Microsoft Edge (`channel="msedge"`), and Pillow. Playwright is a local testing dependency, not a backend runtime requirement.
- The browser checks intercept `/api/**` with synthetic data; they do not log into real accounts, upload datasets, or modify server-side sessions. They exercise canvas dimensions, image fits, transparency, reset, format reload, responsive fitting, pane collapse, zoom, free chart movement, keyboard nudging, drag cancellation, zoom-aware resizing, saved positions, per-chart background switches (including editing and reload), read-only views, and PNG export. A `_dashboard_check.png` screenshot is generated in the working directory.
- Background images and colors must use separate layers so transparency never fades dashboard widgets. Assign image data URLs directly to the background element's `style.backgroundImage`, not through CSS custom properties: multi-megabyte PNGs exceed the browser's custom-property value limit and silently render as `none`. Keep the layer aligned when its parent scrolls. Browser checks cover large PNGs, JPEGs, invalid files, scrolling, transparency, and image reload. Canvas logical dimensions must remain independent of viewport zoom.
- Do not print or commit `backend/.env`, OAuth credentials, or API keys.
- Deployment (Render): the repo root has `requirements.txt` (production deps, includes `gunicorn`) and `render.yaml` (Render Blueprint). The Flask app object is `app:app` inside `backend/`, so gunicorn is started with `gunicorn app:app --chdir backend --bind 0.0.0.0:$PORT --workers 2 --timeout 120`. `backend/app.py` detects production via the `RENDER`/`DYNO` env vars and binds to `0.0.0.0` with `debug=False`; locally it keeps `127.0.0.1` + `debug=True` with the reloader disabled (`use_reloader=False`) so editing files mid-session doesn't kill the running server and interrupt the OAuth callback. `backend/requirements.txt` is the local-dev subset (no gunicorn) and is kept for parity. Set `APP_SECRET_KEY`, `OPENAI_API_KEY`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, and `GOOGLE_REDIRECT_URI` in the Render dashboard; the Google redirect URI must be `https://<service>.onrender.com/api/auth/google/callback` and added to the Google Cloud OAuth client. Note: Render's filesystem is ephemeral — `backend/users.db` (SQLite) and in-memory `SESSIONS` reset on every deploy/restart, so accounts and uploaded datasets do not persist across deploys on the free/starter plans.
- Gunicorn worker count must stay at `--workers 1` (use `--threads` for concurrency). Uploaded datasets live in the module-level in-memory `SESSIONS` dict in `backend/app.py`, which is per-process: gunicorn forks do not share it. With 2+ workers, requests round-robin between forks, so a dataset uploaded via worker A is missing when a later `/api/chart-data`, `/api/kpi`, or `/api/profile` call lands on worker B — surfacing as intermittent "No dataset loaded." errors that appear to fix themselves on retry. Threads share process memory, so `--threads 8` gives concurrency without splitting session state. Raising the worker count requires moving `SESSIONS` into shared storage (Redis, etc.) first.
- OAuth/base-URL guard: `_app_base_url()` and `_google_redirect_uri()` in `backend/app.py` ignore `APP_BASE_URL` / `GOOGLE_REDIRECT_URI` when the configured value points at localhost (`127.0.0.1`, `localhost`, `0.0.0.0`) but the request is *not* being served from localhost. Without this, a stale localhost value — typically from a `backend/.env` that was uploaded to the repo and picked up by `load_dotenv()` on the server — makes the deployed site send Google's OAuth callback and email-verification links to the visitor's own PC, producing intermittent `ERR_CONNECTION_REFUSED` (it "works" only while a local dev server happens to be running). Non-localhost overrides are still honoured.
- Reverse proxy / TLS termination: `backend/app.py` wraps the WSGI app in `werkzeug.middleware.proxy_fix.ProxyFix(x_for=1, x_proto=1, x_host=1, x_port=1)`. Render (like Heroku, nginx, AWS ELB) terminates TLS at a proxy and forwards over plain HTTP with `X-Forwarded-Proto/Host` headers. Without ProxyFix, Flask ignores those headers, so `request.host_url` resolves to `http://<internal-host>` instead of `https://<service>.onrender.com`, which breaks the Google OAuth `redirect_uri` (http vs https mismatch → `redirect_uri_mismatch`) and email-verification links. Do not remove ProxyFix. `SESSION_COOKIE_SECURE` is auto-enabled in production (HTTPS) and disabled locally (HTTP).
